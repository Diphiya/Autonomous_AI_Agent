> **In one line:** Recursion solves a problem by having a function call itself on smaller instances until it reaches a base case.
> 
> Every recursive function needs (1) a base case that returns without recursing and (2) a recursive case that moves the input closer to the base case. >

>

> 
> **Key points:**
> - Always define a base case.
> - Each call must shrink the problem.
> - Calls use stack memory.
> - Many recursive solutions can be rewritten iteratively.
> 
> **Common mistakes:**
> - Forgetting the base case.
> - Recursive step that doesn't shrink the input.
> 
> **Check yourself:** What happens if a recursive function's base case is never reached?

**What it demonstrates:** One message requires two tools in sequence; the router chains them and then stops. Shows the deterministic answer parser and fast path (no routing LLM call for pure answers).

### 🧑 Student
> Explain gradient descent and then give me 3 practice questions

### 🤖 Assistant
> ### 💡 Gradient Descent
> **In one line:** Gradient descent finds a minimum of a loss function by repeatedly stepping in the direction of the negative gradient.
> 
> A model's loss tells you how wrong it is for a given set of parameters. The gradient is the vector of partial derivatives of the loss with respect to each parameter; it points in the direction of steepest increase. Gradient descent updates every parameter as  θ ← θ − η·∇L(θ), where η (the learning rate) controls the step size. Repeating this moves the parameters downhill until the loss stops improving. Variants differ in how much data is used per step: batch (all data), stochastic (one example) and mini-batch (a small subset, the usual choice in practice). Don't worry about the maths yet; focus on the intuition.
> 
> **Analogy:** Walking down a foggy hill: you can't see the valley, but you can feel which way the ground slopes and take a step that way.
> 
> **Example:** Fitting y = w·x to points (1,2),(2,4): with w=0 the MSE gradient is negative, so w increases; after a few steps with η=0.05, w approaches 2.
> 
> **Key points:**
> - The update rule is θ ← θ − η·∇L(θ).

> ### 💡 Binary Search
> **In one line:** Binary search finds a target in a sorted array by repeatedly halving the search interval.
> 
> Keep two indices, low and high, bounding where the target could be. Look at the middle element: if it equals the target you're done; if it's smaller, the target can only be to the right, so set low = mid + 1; otherwise set high = mid − 1. Each comparison discards half of the remaining elements, so the search takes O(log n) steps. It only works because the array is sorted. Don't worry about the maths yet; focus on the intuition.
> 
> **Analogy:** Finding a word in a paper dictionary: open the middle, decide which half the word is in, repeat.
> 
> **Example:** Searching 23 in [2, 5, 8, 12, 16, 23, 38, 56]: mid=12 → go right; mid=23 → found in 2 comparisons.
> 
> **Key points:**
> - Requires sorted input.
> - Halves the search space each step.
> - Runs in O(log n) time.
> - Watch the loop condition (low <= high) and the mid update to avoid infinite loops.
> 
> **Common mistakes:**
> - Using it on unsorted data.
> - Off-by-one errors: setting low = mid instead of mid + 1.
> 
> **Check yourself:** Why does binary search need the array to be sorted?
